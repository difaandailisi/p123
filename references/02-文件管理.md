# 02 · 文件管理

所有文件管理接口都走官方 API `https://api.123278.com/b/api`，鉴权头：

```
Authorization: Bearer <authorToken>
platform: web
app-version: 3
Origin: https://yun.123pan.cn
Referer: https://yun.123pan.cn/
```

> `loginuuid` 经实测**非必需**，不带头也能调通。

## 列目录

```
GET /file/list/new
  ?driveId=0 &limit=100 &next=0 &orderBy=update_time &orderDirection=desc
   &parentFileId=<父目录FileId，0=根> &trashed=false &SearchData=<搜索词，空=列目录>
   &Page=1 &OnlyLookAbnormalFile=0 &event=homeListFile &operateType=1
   &inDirectSpace=false &fileCategory=0 &isSearchOrder=false
```

返回 `data.InfoList[]`，每条关键字段：

| 字段 | 含义 |
|---|---|
| `FileId` | 文件/文件夹唯一 ID（删除、上传预检都靠它） |
| `FileName` | 名称 |
| `Type` | `1`=文件夹，`0`=文件 |
| `Size` | 字节数 |
| `Etag` | 文件 MD5（上传秒传比对用） |
| `ParentFileId` | 父目录 |
| `Status` | 状态（`0` 正常） |

`next` 翻页：返回 `data.Next`，为 `"-1"` 或 `"0"` 表示到底。本技能 `ls()` 自动翻页直到取全。

## 搜索

同一接口，`SearchData=<关键词>`。行为特点（实测）：

- **精确/包含匹配项排在最前**，随后接口会追加少量"最近文件"作兜底（即使匹配很少也会补 8 条左右）。
- 因此搜索结果**不要按大小重排**，保留接口顺序，匹配项自然在最上方。
- 特殊字符（如双下划线）不影响匹配，精确项仍在第一位。

## 新建文件夹

```
POST /file/upload_request
{ "driveId":0, "etag":"", "fileName":"新文件夹", "parentFileId":0,
  "size":0, "type":1, "duplicate":2, "RequestSource":null }
```

- `type:1` 表示文件夹。
- **真实 FileId 在 `data.Info.FileId`**（顶层 `data.FileId` 会是 0，别读错）。

## 删除（移入回收站）

```
POST /file/delete
{ "fileId": <FileId> }
```

- 返回 `code: 7301` 表示成功（"已删除，系统释放空间需要一段时间"），即**移入回收站、可恢复**。本技能把 7301 归一为成功。
- 回收站清空接口（`/file/trash/list` 等）实测 404，不在此技能范围内。

## 账号信息

```
GET /user/info

```
